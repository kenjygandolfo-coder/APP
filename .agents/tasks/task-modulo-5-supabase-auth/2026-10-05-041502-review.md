## High-level view

The save seam is now closed. `App` builds a `handleSaveGoal` that gates on `userId`, maps the Module-2 `MacroResult` through `toSaveMacroGoalInput`, and calls `saveMacroGoal.mutate(...)`; it passes the callback into `MacrosWizard` through a new optional `onSave` prop invoked from the Step-4 save action. Signed-out users still get the local confirmation with no persistence, and the write itself is left to RLS rather than a client-side authz check. The mapper rounds nothing it doesn't need to — `calorie_target` and the gram fields are already integers out of `calculateMacros`, and `tdee` is the only float, which it rounds — and it omits `is_active` so the save strategy owns the single-active invariant.

The bootstrap race is closed with a functional `setState` that overwrites only while `prev.status === 'loading'`. A late-resolving seed can no longer clobber a newer `onAuthStateChange` event, and the subscription stays authoritative once any real event lands. A dedicated `useSession` test defers the seed, fires `SIGNED_IN` first, then resolves the seed with a null session and asserts the authenticated state survives.

Sign-up with email confirmation no longer implies an active session. `makeRegisterSubmit` returns `{ pendingConfirmation: session === null }`, `useAuthSubmit` forwards the resolved result to an optional `onResult` before flipping `submitted`, and `RegisterForm` shows `COPY.register.confirmEmail` when pending and the plain success copy otherwise. Both branches plus the reject path are tested.

The `App` test's `renderApp` is now async and awaits the settled seed, so the suite is free of the `act()` warning that v1 flagged.

### Save mutation is now wired and tested

`App` instantiates `useSaveMacroGoal(userId)` and wraps it in a `handleSaveGoal` callback that returns early when `userId` is falsy and otherwise calls `saveMacroGoal.mutate(toSaveMacroGoalInput(userId, result))`. The callback flows into `MacrosWizard` through the new `onSave?` prop, which the wizard's `handleSave` invokes before setting its local `saved` flag — so the local success confirmation is unchanged whether or not a sink is provided, and signed-out users (no `userId`, no `onSave` effect) still see it without a write.

`toSaveMacroGoalInput` is a pure mapper returning a fresh object: `goal_type: 'mantenimiento'` (Module-2 computes a maintenance distribution), `tdee: Math.round(result.tdee)`, and `calorie_target` / gram fields passed through. That pass-through is correct — `calculateMacros` already sets `calorieTarget = Math.round(tdee)` and each `grams` via `Math.round(...)`, so every persisted field is integer-valued. `is_active` is deliberately omitted, matching `SaveMacroGoalInput` (which keeps it optional for the save strategy).

Two test layers cover this. The unit test asserts the exact mapped shape, non-mutation of the source, and the `is_active` omission. The `saveGoalWiring.integration.test.tsx` renders `App` under a static authenticated `SessionContext`, drives the full wizard, clicks "Guardar mis metas", and asserts the mocked `saveMacroGoal` data function is called once with `user_id` / `goal_type: 'mantenimiento'` and positive `calorie_target` / `protein_g`, while the local status confirmation still renders. Using a static context here also sidesteps the async seed, keeping the integration test warning-free.

### Bootstrap ordering guard

```
mount
 ├─ getCurrentSession() ──(async)──▶ applySeed(session)
 │      setState(prev => prev.status === 'loading' ? toSessionState(session) : prev)
 └─ onAuthStateChange(cb)
        └─ cb(event, session) ─────▶ setState(toSessionState(session))  // always authoritative
```

The seed path reads `prev.status` inside the functional updater, so if an auth event has already moved status off `loading`, the seed is a no-op. Auth events always apply. The `active` flag still prevents writes after unmount. The new "bootstrap race" test exercises the exact adversarial order: it holds `getSession` unresolved, fires `SIGNED_IN` with a real session (status flips to `authenticated`), then resolves the seed with `null` and asserts status and `userId` are unchanged — the behavior the guard is meant to produce.

### Sign-up confirmation branch

The handler contract is now generic: `AuthSubmitHandler<T, R = void>` defaults to `void` so existing void handlers stay compatible, and `makeRegisterSubmit` returns `RegisterResult { pendingConfirmation }` derived from `session === null`. `useAuthSubmit` calls `onResult?.(result)` on the successful path before `setSubmitted(true)`, and `RegisterForm` stores the pending flag to pick between `COPY.register.confirmEmail` ("Revisa tu correo...") and `COPY.register.success`. The error path is unchanged and still collapses provider errors into the friendly non-leaky message. `RegisterForm.test.tsx` covers all four relevant outcomes: null session → confirm-email copy (and explicitly not the active-session success copy), session present → plain success, injected-`onSubmit` success, and a rejected sign-up showing the friendly message without the raw provider text.

### act() warning removed

`App.test.tsx`'s `renderApp` is async and awaits `waitFor(() => expect(screen.getByText(/paso 1 de 4/i)).toBeInTheDocument())`, letting the `getSession` seed settle inside React's act scope. A one-shot `vitest run` grep for `act(`, `not wrapped`, and `Warning:` returns nothing, confirming the suite is clean (the v1 note about the intentional outside-provider throw test remains, and that one is an assertion, not a warning).

### Security and regression check

The redacted-logging invariant is intact — `useAuthSubmit` still logs only `redactCredentials` and `confirmPassword` is dropped in `makeRegisterSubmit` before `signUp`. No hardcoded secrets introduced; the new mapper and wiring take `userId` from the live session and never touch env. The client-side `if (!userId) return` gate is a UX guard, not an authz decision — the write authorization stays with RLS, consistent with the stated constraint. The `@energy` materialized domain is confirmed absent from `git diff 7e443b2..HEAD`.
